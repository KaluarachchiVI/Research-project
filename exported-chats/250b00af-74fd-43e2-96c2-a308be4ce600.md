Yes. The adaptive scheduler has its own SQLite database and it **does persist user/session IDs and related state**.

### Where it’s stored

- **Main scheduler DB**: `adaptive_scheduler.db` (SQLite), configured in `older/src/database/models.py`:
  - `Session` table stores:
    - `session_id` (primary key)
    - `user_id`
    - `start_time`, `end_time`
    - `chronotype`, `task_type`, `algorithm`
    - various flags like `is_active`, `praboth_session_id`, `schedule_json`, `current_interval_index`, etc.
  - Other tables (`KeystrokeEvent`, `ContextVector`, `Action`, `Reward`, `MicroEMA`, `Metrics`) all link back to `Session` via `session_id`.

- **Persistent active-session state**: there is a separate `active_sessions` table managed by `SessionState` in `older/src/session_manager/session_state.py`:
  - Stores `session_id`, `user_id` and a JSON blob (`state_json`) with the full active session state so it can be restored after restarts.

So from the adaptive scheduler side, both **`user_id`** and **`session_id`** (plus all actions, rewards, context vectors, and metrics) are saved in a database, not just held in memory.
