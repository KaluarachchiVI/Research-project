### Why you saw "Failed to fetch"

The frontend calls the **scheduler API** at `NEXT_PUBLIC_SCHEDULER_API_BASE` (default `http://127.0.0.1:5000`) when you click **"Start Time Block Session"**.  
**"Failed to fetch"** means that request never got a response. Common causes:

1. **Scheduler backend not running** – nothing listening on port 5000.
2. **CORS** – backend not allowing requests from your frontend origin (e.g. `http://localhost:3000`).
3. **Wrong URL** – `NEXT_PUBLIC_SCHEDULER_API_BASE` points to the wrong host/port.
4. **Firewall/network** – request blocked before it reaches the server.

Previously the UI didn’t show this: the error was only in the console and the session never started.

---

### Changes made

1. **User-visible error**
   - If the scheduler request fails (including "Failed to fetch"), a **red alert** appears under the session config:
   - **"Scheduler error: Cannot reach the scheduler. Ensure the scheduler backend is running (e.g. on port 5000) and that CORS allows this origin. Check NEXT_PUBLIC_SCHEDULER_API_BASE."**
   - For other errors, the actual error message is shown.

2. **Session only starts after scheduler succeeds**
   - When the scheduler is enabled, the session (and dashboard) is set **only after** `startTimeBlockSession` succeeds. If the request fails, the session is not marked active and the dashboard doesn’t show, so the state stays consistent.

3. **Loading state**
   - The button shows **"Starting…"** and is disabled while the request is in progress, so you don’t double-submit.

4. **`--color-error-bg`**
   - Added in `globals.css` so the error banner and any other error backgrounds render correctly.

---

### What you should do

1. **Run the scheduler backend** on the port your frontend expects (e.g. 5000), or point the frontend to where it actually runs using `NEXT_PUBLIC_SCHEDULER_API_BASE` in `.env.local`.
2. **Enable CORS** on the scheduler so it allows your frontend origin (e.g. `http://localhost:3000`).
3. If you don’t use the scheduler at all, **unset** `NEXT_PUBLIC_SCHEDULER_API_BASE` (or leave it empty). Then the app won’t call the scheduler; note that in the current design the main dashboard only appears when a scheduler session is started, so without the scheduler you won’t see the timer/cards. If you want a “local-only” session mode without the scheduler, that can be added as a separate change.
