## Product-grade Adaptive Scheduler Stack (Phase 1)

It’s a **hybrid client–server** stack for adaptive scheduling and cognitive-load-aware behavior.

### Main components

| Component | Role | Where it runs |
|-----------|------|----------------|
| **CLE** (Cognitive Load Estimator) | Estimates real-time cognitive load from keyboard/mouse events | **Client** (FastAPI, port 8000) |
| **Intent-Lock** | Overlay that uses load + exit-intent (impulsive vs genuine) and applies “friction” before ending sessions | **Client** (backend 8001, Next.js 3000) |
| **Adaptive Scheduler API** | Manages time-block sessions, DB, metrics; receives session-end + Intent-Lock data | **Server** (Flask, port 5000) |
| **Yuvidu** | Heatmap service: weekly/hourly recommendation visualizations for dashboards | **Server** (FastAPI 5001, React/Electron frontend 5123/3001) |

### High-level flow

1. **OS hooks** send keyboard/mouse events to **CLE** (`POST /events`).
2. **CLE** exposes a cognitive load estimate (`GET /estimate`, value in [0, 1]).
3. **Intent-Lock** uses that estimate and, on “End Session”, calls its backend for exit classification and friction; after friction it calls the **Scheduler API** (`/api/time-block/end`) with session id and optional Intent-Lock metadata.
4. **Scheduler** stores sessions in `adaptive_scheduler.db` and can surface or link to **Yuvidu** heatmaps for planning.

### Project layout (from `product-app`)

- **`server/`** – Scheduler API + Yuvidu backend/frontend wrappers and config.
- **`client/`** – CLE, Intent-Lock, and launchers to run them together.
- **`shared/`** – Cross-service types and small client libs.

Code lives in `older/` and `newer/` (e.g. `newer/yuvidu`, `newer/praboth-newfx` for CLE, etc.); `product-app` adds **wrappers and configuration** to run the integrated product, not duplicate those codebases.
