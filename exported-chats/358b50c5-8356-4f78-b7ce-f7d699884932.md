Here’s what you need to **check the last event recorded by the CLE** (Cognitive Load Estimator):

---

## 1. **Last policy event (via CLE API)**

If the CLE service is running (e.g. on port 8000):

- **Endpoint:** `GET http://127.0.0.1:8000/policy/events?limit=1`
- **Example (browser or curl):**  
  `http://127.0.0.1:8000/policy/events?limit=1`  
  or  
  `curl "http://127.0.0.1:8000/policy/events?limit=1"`

Response shape: `{"events": [{ "occurred_at", "event_type", "reason", "metadata" }, ...]}` (newest first). So the first element is the last policy event.

---

## 2. **Last raw input event (keyboard/mouse)**

The CLE does **not** expose an HTTP endpoint for raw input events. They are only in the SQLite DB.

- **Database (default):** `data/state.db` relative to where the CLE runs (e.g. `newer\praboth-newfx\data\state.db`), or the path set in your config (e.g. `policy_1.toml` → `StorageConfig.path`).
- **Table:** `input_events`  
  Columns: `event_id`, `session_id`, `occurred_at`, `source`, `payload_json`, `hop_index`.

**Query for the last recorded input event:**

```sql
SELECT event_id, session_id, occurred_at, source, payload_json, hop_index
FROM input_events
ORDER BY event_id DESC
LIMIT 1;
```

You can run this with any SQLite client, or from the project root, for example:

```powershell
cd "c:\Users\ASUS TUF\Desktop\Research project\newer\praboth-newfx"
sqlite3 data/state.db "SELECT event_id, occurred_at, source, payload_json FROM input_events ORDER BY event_id DESC LIMIT 1;"
```

(If you don’t have `sqlite3` in PATH, use DB Browser for SQLite or a small Python script with `sqlite3`.)

---

## 3. **Quick sanity checks**

- **CLE up and responding:**  
  `GET http://127.0.0.1:8000/health`
- **Latest cognitive load (confirms events are being used):**  
  `GET http://127.0.0.1:8000/estimate`

---

## 4. **Local diagnostics (no HTTP)**

From the CLE package directory (e.g. `newer\praboth-newfx`), you can run the console CLI (it uses the same DB and shows counts + latest policy events):

```powershell
.\.venv\Scripts\python.exe -m cog_py_est.tools.console_cli --config policy_1.toml
```

It does **not** print the last raw input event; for that you still need the SQL query above on `input_events`.

---

**Summary:**  
- **Last event (policy):** call `GET .../policy/events?limit=1` on the running CLE.  
- **Last event (raw input):** query `input_events` in `data/state.db` with the SQL above (and ensure CLE is running from the directory that uses that DB, or adjust the DB path to match your config).
